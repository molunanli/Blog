为什么 2026 年还要自己搭一个博客：三笔账算完再决定

✍️ 博主 📅 令和8年11月3日 ⏱ 阅读约 18 分钟
#Hexo #教程 #独立博客

先说一个不太好听的事实：你在平台上写的东西，著作权可能还是你的，但它明天还在不在、以什么样子存在，不由你决定。

不是危言耸听，是这类事的常见形态：

  • 平台改版，你的专栏被折叠进「历史内容」，链接还在，但没人找得到
  • 账号因为一次误判被限流或封禁，几年的东西自己都打不开
  • 想搬走的时候发现，编辑器导出的富文本粘到别处全是乱码，图片还带着防盗链
  • 文章里放一张自己画的图，被压缩到糊成一团，改不回来

这些都不是「平台坏」，而是你在用一个你不拥有的房子装修。

但这篇文章不是劝你自建。2026 年了，自建博客早就不是唯一答案，甚至不是多数人的最优解。我只想把这件事的账算清楚——算完你自己决定。

一、先把两件事分开：写东西，和拥有一个站

很多人把这两件事混在一起，所以一谈自建就觉得「要从头学做网站」。其实完全可以拆开：

写作工具 发布渠道
是什么 你用来敲字的地方 文章最后被谁托管、被谁知道
举例 Typora / Obsidian / VS Code / 平台自带编辑器 公众号、知乎、小红书、自己的站
换掉的成本 低（文件在那，换个软件接着写） 高（链接、读者、SEO 全都归零）

内容是资产，渠道是流量。 这两件事可以分开配置：你完全可以在本地用 Markdown 写，然后一份发公众号、一份发自己的站。

一旦想通这一点，「自建博客」就从「我要做网站」降级成「我多了一个发布渠道」——心理负担立刻小一半。

二、三笔账

判断该不该做，不用讲情怀，算三笔就够了。

2.1 第一笔：钱

项 平台托管 自建（本站方案） 自建（加自有域名）
站点费用 0 元 0 元（GitHub Pages 免费） 0 元
域名 平台给，你不拥有 xxx.github.io（也是平台给） 60~120 元 / 年（.com）
HTTPS 证书 平台负责 平台自动配 Let’s Encrypt 免费
存储与流量 平台限额，规则会变 仓库约 1 GB、每月 100 GB 流量（软限制） 同左
备案 平台负责 境外托管，不需要 若接国内 CDN 则需要

最贵的一档是「买域名」，一年六十到一百二，等于一个月一杯咖啡。钱从来不是门槛。

顺带说清 GitHub Pages 的那两个限制：仓库 1 GB、每月 100 GB 流量，都是软限制——一个纯文字加手绘图的中文技术博客，写满一百篇也很难碰到。真碰到了，说明你该考虑 CDN 了，那是好事。

2.2 第二笔：时间

  • 一次性：从空目录到一个能访问的站，按本站的真实记录是五个小时左右（含踩坑）。熟悉流程之后四十分钟能重来一遍。
  • 每篇的增量：几乎没有。你还是用 Markdown 写，多出来的只是「生成 + 推送」这一步，熟练后一分钟。写文章本身不会因为自建而变慢。
  • 长期：这是唯一真实的成本——出了问题要自己修。

很多人以为自建的代价是「每次发文都要折腾半小时」。不是的。真正的代价是某天晚上十点，你发现首页白了，而没有人能帮你查。

2.3 第三笔：维护

这里有个反直觉的结论：静态博客的维护量，比大多数人想象的少得多。

因为它没有数据库、没有后台管理界面、没有登录、没有插件市场。没有这些东西，也就没有对应的漏洞。攻击面接近于零——没人能「拖库」，因为压根没有库。

需要照看的只有三样：

一年两次体检，每次一小时，够了。

2.4 外加一笔：失控风险

前三笔都是一次性投入，这一笔是长期挂着的。

图 1：前三笔都能算清，最后一笔算不清——它取决于别人什么时候改规则。

平台的风险不是「它会害你」，而是你不在决策桌上。改版、限流、调整推荐、下架某个功能，都不需要征求你的意见。你的应对方式只有一种：接受，或者走。

自建的风险是另一种：只有你自己能关掉它，也只有你自己能救它。

三、自建能得到什么

具体一点，不写「自由」「掌控」这种空词。

① 所有权是物理的。
你的全部内容就是 source/_posts/ 里的一堆 .md 文件，加上一个 images/ 目录。拷走这个文件夹，你就带走了全部——不需要导出工具，不需要求人，不需要联网。

② URL 是永久的。
平台的文章链接会随改版失效，自建站的链接只要域名和仓库在就一直在。这件事对「写给自己看」尤其重要：三年后你想翻回某篇，链接还在。

③ 没有推荐算法，没有开屏广告，没有「关注后查看全文」。
读者点开就是你写的东西，从头到尾，没有中间商。

④ 排版你说了算。
本站所有配图都是手写 SVG——矢量、体积几 KB、能跟着主题配色走。这种事在富文本编辑器里基本做不到，在自建站里只是日常。

⑤ 每一版都能 diff。
Git 记着你每一次改动。写错了想看看上一版怎么写的，git diff 一句话。文章改过几次、什么时候删掉了一段，全都有记录。

⑥ 离线可读、可打印、可整站打包。
整个站是一堆静态文件。想给朋友一份，压缩一下发过去就行。

四、自建会失去什么

这一节才是重点。前面那些好处，平台上多写几篇也能部分拿到；下面这些损失，只有自建才有。

失去的 有多疼
流量 平台有推荐池，新号也可能被推到几万人面前；自建站的第一年，读者大概率只有你和爬虫
现成的移动端体验 平台有 App，你在地铁上能随手发；自建站要发文章，得打开电脑
互动生态 点赞、收藏、转发链路、私信，平台全给你配好了；自建站得自己接评论（本站用 Giscus）
傻瓜式编辑器 图片上传、拖拽排版、草稿箱、定时发布，全得自己张罗
兜底的人 平台挂了有人修；你的站挂了只有你

把这几条摆在一起，结论其实很清楚：

自建博客不是「更好」，是「更可控」。它用流量换控制权。

所以问题从来不是「自建好不好」，而是「你更需要哪一个」。

五、四个问题，判断你属于哪一种

不用纠结，回答四个问题，符合就打勾：

图 2：打勾数量比直觉判断准。这一栏主要服务第 4 种人。

我的判断标准是这样的：

  • 0~1 个勾：别折腾。平台完全够用，把省下的时间拿去写，比什么都强。
  • 2~3 个勾：两边都写。平台负责被看见，自建负责存得住——每季度从平台导出一份 Markdown 存本地，成本几乎为零。
  • 4 个勾：直接自建。你要的本来就不是流量。
💡 一个折中做法很多人的真实需求是「既想被看见，又怕东西丢」。那就别二选一：平台照发，同时把源文件留在本地 Git 仓库里。哪怕先不搭站，这一步也值得做——它保证你随时可以搬走。

六、本站的配置单（不藏私）

既然要谈取舍，就得先交代自己站在哪儿。本站是最省的那一档，一分钱没花：

项 本站选择 为什么
生成器 Hexo 7.x 纯静态、Markdown 原生、插件生态老而稳
主题 mangaka（自制改造） 想要的控制权，模板在自己手里才叫控制权
托管 GitHub Pages（子路径 /Blog/） 免费、自带 HTTPS、不需要备案
域名 暂时没有，用 molunanli.github.io/Blog 先跑起来。换域名的后路已经留好了（第 3 篇讲）
部署 本地脚本 + 手动推 gh-pages hexo deploy 在本机不可用；手动流程反而更好排错（第 4 篇讲）
评论 Giscus（GitHub Discussions） 无广告、不用另注册账号、数据在仓库里
搜索 生成期建索引 纯前端，不需要服务端
统计 第三方（后面接） 接受它的代价，但只装一个、只看 5 个指标（第 12 篇讲）

年成本：0 元。写作之外的时间成本：每月约十分钟。

这张表里有两处是「将就」：域名和部署方式。我特意留着，因为先把站跑起来，比先把站配到完美重要得多。等真的觉得麻烦了，再升级——第 3、4 篇写的就是这两条升级路。

七、三条底线

「电脑维修」那个栏目立了三条铁律。这个栏目也立三条——它们决定了你是在「自建」，还是在「换一个平台」。

⚠️ 底线一：内容必须能导出源文件必须是你本地的纯文本（Markdown 最好），图片必须是本地文件。如果哪天你的内容只存在于某个后台的数据库里，靠一个「导出」按钮才能拿出来，那你只是换了个房东。
※ 底线二：站点必须能搬走生成器可以换（Hexo 换 Hugo 都行），托管可以换（GitHub Pages 换 Cloudflare Pages 都行），域名可以换。凡是「换了就得重写全部文章」的方案，都不算自建。
※ 底线三：改动必须能回退用 Git 管着。改坏了、删错了、主题升级崩了，一条命令回到上一个好版本。没有版本控制的自建站，本质上是一次性用品。

违反任意一条，自建就退化成了「另一个平台」，而且还是个没人维护的平台。

八、这一季要写什么

十二条，分四条线，顺序不能反：

图 3：先解决「能不能打开」，再解决「好不好读」，最后才谈「有没有人来」。

反过来做的典型症状是：站还没上线，先研究了两周 SEO；首页还是空白，先把统计脚本装了三家。

💡 两条捷径第 2 篇和第 5 篇是本站九月份就发过的旧文（部署指南、写作手册），内容仍然有效。这次只给它们补上系列导航，不重写、不搬家——没必要为了栏目整齐去重造轮子。

九、这个栏目给什么，不给什么

说清楚边界，省得你读到一半失望。

给：

  • 一条已经跑通的路线（Hexo 7 + GitHub Pages + 子路径部署），每一步都有「预期看到什么」
  • 本站真实踩过的坑，不是从文档里抄来的
  • 可以直接复制的完整配置片段，不留「此处自行修改」
  • 出问题时怎么自己排错——这比记住命令重要得多

不给：

  • 不教前端框架。这个栏目不写 Vue、不写 React，也不需要你会
  • 不承诺流量和变现。自建站第一年没人看是常态，我不打算假装不是
  • 不推荐「一键美化」「一键 SEO」这类黑箱插件——出问题时你连它在干什么都不知道
  • 不替你选平台。这篇只是把账算清，选哪个是你的判断

十、如果你决定不搭

那也挺好，而且下面这件事你现在就该做：

texttext
1
2
3
4
1. 在平台正常发文
2. 每季度导出一次全部文章，存成本地 Markdown
3. 图片一起存下来（别只存链接）
4. 这个文件夹丢进网盘或 Git 仓库，最好再加一块移动硬盘

这四步花不了半小时，但它保证了一件事：哪天你想搬，你搬得走。

很多人不是被平台困住的，是被自己「从来没存过」困住的。

写博客这件事，最难的从来不是搭站。搭站是一次性的技术问题，有标准答案；难的是持续写，那没有标准答案。

所以这个栏目存在的意义，不是让你多掌握一门手艺，而是把「发布」这件事的成本压到足够低——低到你想写的时候，不会因为「还要折腾网站」而放弃。
