一条目录项被压扁了：flex 收缩、省略号与悬浮提示

✍️ 博主 📅 令和8年11月3日 ⏱ 阅读约 15 分钟
#独立博客 #CSS #JavaScript

新文章发出去不到半小时，读者（其实是我自己）就发现目录坏了。

截图是这样的：红色高亮的那一项里，标题被切成两行，第一行在色块里，第二行「有一个站」掉到了色块外面，正好压在下一项「二、三笔账」的头上。

第一反应很直接：加个省略号不就完了。

加了，没用。

这篇记录一下这个坑——它比我一开始想的深一点，而且犯错的不是「忘了写省略号」，是把 CSS 的一个默认值当成了没事。

二、为什么加了省略号也没用

我第一版是这么改的：

csscss
1
2
3
4
5
.toc-link {
    white-space: nowrap;
    overflow: hidden;
    text-overflow: ellipsis;
}

省略号确实出现了鸡生蛋的问题：它让文字变成一行，但容器还在压它，所以看到的还是一个 40px 高的盒子，文字在盒子里被截断——视觉上从「掉到下一项」变成了「下半截被切掉」。

问题回到根上：为什么这个盒子是 40px，而不是内容需要的 56px？

.toc-link 上写的是 min-height: 40px，那是下限，不是上限。内容 56px 时它应该长到 56px 才对。

除非——它被别的东西压了。

图 1：同一个组件，左边是「被压回 40px 的盒子」，右边是「单行省略」。

三、定位：把盒子量一遍

这种问题的正确姿势不是猜，是量。打开 DevTools，选中那个目录项：

texttext

Elements → 选中 .toc-link
右下 Computed → height: 40px        ← 盒子的实际高度
               └ 但内容呢？看 Layout 面板的 scrollHeight，或者直接在
                 Console 里敲：$0.scrollHeight

Console:
  $0.clientHeight   → 40    盒子的可见高度
  $0.scrollHeight   → 56    内容实际需要的高度
  getComputedStyle($0).flexShrink → "1"

三个数字一摆，结论就出来了：

内容要 56px，盒子只有 40px，而且它还是 flex-shrink: 1。

.toc-list 是 display: flex; flex-direction: column，并且有 max-height: 62vh。二十来个目录项加起来远超这个高度，于是 flex 容器开始压缩子项——这是 flexbox 的默认行为（flex-shrink: 1）。

而 min-height: 40px 恰好把「能被压到多小」钉在 40px。所以：

多出来的 16px 无处可去，直接画在盒子外面

这就是「文字跑出框外」的完整机制。 加省略号只是让内容从两行变一行，但如果盒子仍然被压到 40px，视觉上依然是截断而不是省略。

💡 一个判断口诀凡是「盒子明明该撑开却没撑开」，先查两件事：父级是不是 flex/grid 且尺寸受限，子项是不是默认会收缩。90% 的诡异溢出都在这两条里。

四、修法：两行 CSS

知道病因就好办了，两件事一起做：

csscss
1
2
3
4
5
6
7
8
9
.toc-link {
    /* ① 不许被 flex 压扁 */
    flex: 0 0 auto;

    /* ② 单行 + 省略号 */
    white-space: nowrap;
    overflow: hidden;
    text-overflow: ellipsis;
}

第一条是关键，也是我一开始漏掉的。flex: 0 0 auto = flex-grow: 0 / flex-shrink: 0 / flex-basis: auto，意思是「别长、也别缩、按内容自然高度」。加上它，盒子就是稳稳的 40~56px，不会再被挤。

第二条让每项恒为一行，于是 min-height: 40px 变成实际高度 40px，长度恒定、视觉整齐。

⚠️ 只加第二条的后果`white-space: nowrap` + `overflow: hidden` 单独用，确实不会「溢出到下一项」了，但盒子仍可能被 flex 压到 40px 以下（如果你的 `min-height` 更小），文字会被切掉半截——比溢出更难看，因为你都不知道少读了什么。

六、省略号之后：完整标题怎么看

标题被截了，得让人能看到全文。这有三种做法，差别比想象中大。

图 2：都叫「悬浮提示」，能做的事完全不是一回事。

① 原生 title 属性——最简单，模板里加一句 title="<%= h.text %>" 就完事。但它延迟约一秒、样式完全不可控、移动端长按才出，而且会把浏览器的灰色小框硬生生盖在这套手绘风格上。

② 纯 CSS 的 ::after——content: attr(data-toc-text)，样式随你定。但它有个致命问题：.toc-list 是滚动容器，overflow 会把溢出的伪元素直接裁掉。提示框要么被切一半，要么完全不显示。这就是「纯 CSS 更优雅」在真实场景里的翻车点。

③ JS 浮层——自己建一个 position: fixed 的元素挂在 body 上，不受任何祖先的 overflow 影响。多写三十行，换来三件事：只在真截断时出现、位置能夹进视口、键盘聚焦也能显示。

我选了第三种。核心就一行判断：

jsjs
1
2
3
function isClipped(el) {
    return el.scrollWidth > el.clientWidth + 1;
}

scrollWidth 是内容宽度，clientWidth 是可见宽度。只有内容真的超出去了才弹提示——否则每一项都弹，提示和原文一模一样，纯噪音。

(function initTocTip() {
    if (!tocLinks.length) return;
    var canHover = window.matchMedia && window.matchMedia('(hover: hover)').matches;
    var tip = null;

    function ensureTip() {
        if (tip) return tip;
        tip = document.createElement('div');
        tip.className = 'toc-tip';
        tip.setAttribute('role', 'tooltip');
        document.body.appendChild(tip);
        return tip;
    }

    function place(link) {
        var t = ensureTip();
        var r = link.getBoundingClientRect();
        // 水平方向夹进视口
        var left = Math.max(10, Math.min(r.left, window.innerWidth - t.offsetWidth - 10));
        var top = r.bottom + 8;
        // 下方空间不够就翻到上面
        if (top + t.offsetHeight > window.innerHeight - 10) {
            top = Math.max(10, r.top - t.offsetHeight - 8);
        }
        t.style.transform = 'translate(' + Math.round(left) + 'px,' + Math.round(top) + 'px)';
    }

    function show(link) {
        if (link.scrollWidth <= link.clientWidth + 1) return;
        var t = ensureTip();
        t.textContent = link.getAttribute('data-toc-text') || link.textContent;
        t.classList.add('is-on');
        place(link);
    }

    function hide() {
        if (tip) tip.classList.remove('is-on');
    }

    tocLinks.forEach(function (link) {
        var full = link.getAttribute('data-toc-text');
        if (!canHover) return;
        link.addEventListener('mouseenter', function () {
            if (full) link.removeAttribute('title');  // 屏蔽原生提示，避免两个一起弹
            show(link);
        });
        link.addEventListener('mouseleave', function () {
            if (full) link.setAttribute('title', full);
            hide();
        });
        link.addEventListener('focus', function () { show(link); });
        link.addEventListener('blur', hide);
    });

    window.addEventListener('scroll', hide, { passive: true });
    window.addEventListener('resize', hide);
})();

七、模板层要配合改一行

提示要显示全文，就得把全文带在 DOM 上。目录是模板渲染的，改一行：

plaintextplaintext
1
2
3
4
<a class="toc-link toc-link--h<%= h.level %>"
   href="#<%= h.id %>"
   title="<%= h.text %>"
   data-toc-text="<%= h.text %>"><%= h.text %></a>

data-toc-text 给 JS 用，title 给没开 JS 的读者兜底（JS 启动后会在悬停时临时摘掉它，避免两个提示一起弹）。

💡 为什么不用 JS 直接读 textContent因为文字被 CSS 截断时，`textContent` 拿到的仍是完整文本——这没错。但一旦以后给目录项加了「序号徽章」「状态点」之类的子元素，`textContent` 就会把它们的文字也混进来。用一个显式的 `data-` 属性存，比依赖 DOM 结构稳。

function keepTocVisible(link) {
    // 桌面端滚外层，移动端滚目录本身
    var box = window.innerWidth >= 900
        ? link.closest('.toc-sticky')
        : document.getElementById('tocList');
    if (!box || box.scrollHeight - box.clientHeight < 8) return;

    var lr = link.getBoundingClientRect();
    var br = box.getBoundingClientRect();
    if (br.height < 8) return;          // 移动端面板收起时 rect 全 0，直接跳过

    var pad = 6;
    if (lr.top < br.top + pad) box.scrollTop -= (br.top + pad - lr.top);
    else if (lr.bottom > br.bottom - pad) box.scrollTop += (lr.bottom - br.bottom + pad);
}

□ 键盘 Tab 到目录项：提示出现，移开后消失

□ 缩放窗口到 320px 宽：提示不超出左边或右边

第 4 条最容易被忽略，也最能说明「你做对了没有」——没被截断的项也弹提示，等于没做。

十、三条经验

① 「加省略号」不是排版问题的解药。
text-overflow: ellipsis 只负责「把溢出的文字换成省略号」，它不管盒子为什么小。盒子尺寸错了，省略号也会跟着错。先量尺寸，再谈截断。

② flex 的默认值是会咬人的。
flex-shrink: 1 在「容器高度受限 + 子项内容变高」时会主动压扁子项，而 min-height 只是兜底，不是保护。凡是列向 flex + max-height 的组合，子项都该显式写 flex: 0 0 auto。

③ 纯 CSS 方案在「滚动容器里」经常失效。
:hover::after 看起来最优雅，但祖先一旦有 overflow，绝对定位的伪元素就会被裁。要判断一件事：「这个元素会不会被祖先裁掉」——答不上来就别省那三十行 JS。

※ 顺带一句这次没做浏览器截图验证——无头 Chrome 在当前环境下截不出图（`rc=0` 但文件不生成）。上面的验证清单是靠 DevTools 规则推算 + 逐条人工核对的，交付时也如实说明了这一点。没有视觉证据的时候，就把判断依据写清楚，别含糊过去。
