jp-blog 写作与发布手册：从新建文章到上线

✍️ 博主 📅 令和8年9月4日 ⏱ 阅读约 9 分钟
#Hexo #教程 #jp-blog

上一篇《零成本拥有自己的博客》讲清楚了”怎么把站弄上线”，欢迎页介绍了主题的结构和配置。这篇是日常写作手册——覆盖你之后每次发文章的完整路径：新建 → 写正文 → 本地预览 → 发布 → 核验。

先记住整条工作流，再逐个拆解：

2

写文章                 预览                 发布                  核验

source/_posts/新建     localhost:4000/Blog/    + 推送 gh-pages        归档/搜索/标签同步更新

一、新建一篇文章

两种方式任选：

bashbash
1
2
3
4
5
# 方式一：命令生成骨架（推荐，会自动创建带 front-matter 的文件）
cd my-blog
npx hexo new post "我的新文章"

# 方式二：直接手写 —— 在 source/_posts/ 下新建 xxx.md 即可
⚠️ 文件名决定网址Hexo 的文章地址取自**文件名**，不是 front-matter 里的 `title`。所以文件名就是永久的 URL，起名时想清楚：用英文小写短横线（`kebab-case`），别带日期前缀，也避免日后改名（改名 = 换链接，旧分享和搜索引擎都会断）。

文件名的 slug 与最终地址的关系：

texttext
1
2
3
source/_posts/deploy-hexo-github-pages.md
        ↓ 生成
/Blog/2026/09/deploy-hexo-github-pages/

文章在 _posts 目录下会按年/月归档（/Blog/2026/09/），这是 Hexo 的默认行为，不用手动建目录。

二、front-matter：一篇文章的”档案卡”

文件开头的 --- 之间的 YAML 就是 front-matter。一个完整示例：

yamlyaml

---
title: jp-blog 写作与发布手册
date: 2026-09-04
slug: writing-publishing-manual        # 可选：覆盖文件名生成的地址
categories:
  - 使用指南                            # 多级分类用缩进列表
tags:
  - jp-blog
  - Hexo
featured: true                          # 可选：首页卡片显示 🔥 精选
readTime: 9                             # 可选：估算阅读分钟数（不写会自动估算）
excerpt: "一句话摘要，用于卡片和分享。"   # 可选：不写则取正文开头
toc: false                              # 可选：本页关闭目录（默认开）
---
字段 用途 不写会怎样
title 文章标题（标题栏、列表卡片、正文 H1） 必填
date 发布/归档日期，决定文章出现在哪年哪月 默认取文件创建时间，建议显式写
slug 覆盖文件名的地址别名 用文件名
categories 分类（可多级），卡片上显示第一个 显示”未分类”
tags 标签，生成独立标签页 无标签
featured: true 首页卡片加”🔥 精选”徽章 普通卡片
readTime 手动指定阅读时长 按字数自动估算
excerpt 列表卡片摘要 自动截取正文开头
toc 控制文章页右侧/顶部目录 默认开启
💡 技巧分类建议**只用一个主分类**（本主题卡片在 meta 区只展示第一个分类的 chip）；标签则可以多打几个，方便聚合阅读。写完草稿想先不公开？把文件移出 `_posts`（比如放到 `source/_drafts/` 自己留档），或加 `published: false`。

三、正文写作：Markdown + 主题特性

正文用标准 Markdown。本主题在纯 Markdown 之上额外提供了几个”增强件”。

1. 标题、列表、引用、表格

## 二级标题（自动进文章目录）
**加粗**、*斜体*、`行内代码`

- 无序列表

> 引用块

| 列1 | 列2 |
| --- | --- |

普通 Markdown 表格会被主题自动套上滚动容器（.table-scroll），列数太多时在窄屏可以横向滑动，不会撑破页面。

2. 代码块：语言标签、复制、长代码自动折叠

代码块用围栏写法，务必标注语言——这决定了主题能否给它加语言徽标和语法着色：

markdownmarkdown
1
2
3
4
5
6
7
```js
console.log('hi');
```

```bash
hexo generate
```

渲染后每个代码块自动具备：

  • 顶部语言徽标（如 JS、BASH）
  • 左侧行号、右上角「复制」按钮（一键拷全文）
  • 超过约 190px 高的长代码会自动折叠，显示朱红「展开 ▼」按钮和底部渐隐遮罩——文章里的超长配置/脚本不会再撑满整屏。想全量看就点开，看完了可以再收起。
💡 技巧在 Markdown 里示范"代码块怎么写"时，最外层要用**四个反引号**包裹（```` ``` ````），否则内层三个反引号会提前闭合围栏。

3. 提示框：三种颜色，顶格写 HTML

需要”重点提示、经验技巧、警告”时，用主题的提示盒。它是原生 HTML，写的时候必须顶格（行首不能有空格）：

※ 说明蓝色 = 补充说明，交代背景或前提，如："这篇配置在主题 `_config.yml` 里。"
💡 技巧金色 = 经验技巧，放踩坑后的心得，如："改主题样式不用重启服务，刷新即可。"
⚠️ 注意红色 = 警告，提醒容易出错的地方，如："md 里的 HTML 一旦行首缩进 4 个空格，会被判成代码块而原样转义。"

对应的源码长这样（注意：下面只是”代码示范”，所以包在围栏里；真正要显示提示框时，这行 HTML 要顶格直接写在文章里，不要用围栏）：

htmlhtml
1
<div class="note note--warn"><span class="note-title">⚠️ 注意</span>红色是警告，提醒读者这里容易出错。</div>
⚠️ 最常见的写作事故如果你发现某段文字在页面里变成了"带等号转义的源码"而不是效果，十有八九是那行 HTML 开头不小心缩进了。规则很简单：**Markdown 文本随意缩进，但 HTML 标签必须顶格**。

4. 插图

图片推荐统一放进 source/images/（没有就自己建一个），正文里用相对站点根的路径引用：

markdownmarkdown
1
![替代文字说明，方便读屏](images/xxx.png)
※ 说明正式上线后路径要带站点前缀（本站是 `/Blog/images/xxx.png`）。本地预览和线上都跑一遍确认图片能出来再发布。当前站点配置 `post_asset_folder: false`，所以**不支持**在 `_posts` 下建同名文件夹放图——统一走 `source/images/` 最省心。

四、本地预览

bashbash
1
2
3
4
# 起本地服务（建议固定端口，方便记住预览地址）
npx hexo server -p 4000
# 浏览器打开（注意带 /Blog/ 前缀，无前缀会 404）
# http://localhost:4000/Blog/

预览时改 source/_posts/ 下的 md、source/css/style.css，Hexo 会热更新，刷新页面即可看到；改站点根目录 _config.yml 的配置则需要重启服务。

⚠️ 生成前先停服务Hexo 的 server 会一直占用 `db.json`（数据库缓存）。如果不停服务直接 `hexo generate`，可能遇到文件锁导致生成失败，或更隐蔽地——生成用了旧的缓存，**新文章没进首页列表**。所以每次发布前：先停掉服务进程，再生成。核验方法见第六节。

五、发布上线

bashbash
1
2
3
4
5
6
7
# 1. 先停掉预览服务
# 2. 清理缓存并生成
rm -f db.json        # 缓存文件删掉重建（比 hexo clean 更直接）
npx hexo generate

# 3. 推送：装过 hexo-deployer-git 的用一条命令
npx hexo deploy

如果用不了 hexo deploy（比如网络/权限受限），手动推送产物分支效果相同：

bashbash
1
2
3
4
5
D=".dpl_$(date +%s)" && mkdir -p "$D" && cd "$D"
git init -q && git checkout -q --orphan gh-pages
cp -rf ../public/. .
git add -A && git -c user.name="<用户名>" -c user.email="<邮箱>" commit -q -m "deploy"
git push -q -f git@github.com:<用户名>/<仓库名>.git gh-pages

两种方式的原理与区别，上一篇部署教程里有详细解释。发布后 Pages 的 CDN 要 1~2 分钟刷新，强刷（Ctrl+F5）能看到最新。

六、发布后的核验清单（每次必做）

生成完、推送前，花十秒确认这几件事，能省掉一半的”为什么没生效”：

bashbash
1
2
3
4
5
6
7
8
# 1. 首页真的出现新文章了吗（看生成时间 + 标题出现次数）
ls --time-style=+%H:%M:%S public/index.html
grep -c "文章标题关键词" public/index.html

# 2. 归档页、search.json 同步更新
ls -d public/archives/*/*/            # 应该有新文章的归档目录
# 3. 图片/资源引用是否带对前缀
grep -o 'src="[^"]*"' public/2026/09/<新文章>/index.html | head
⚠️ "生成了但首页没新文章"这是静态博客最常见的"幽灵问题"：详情页、搜索都更新了，唯独首页列表是旧的。原因几乎都是——残留的 server 进程把旧的 `db.json` 又写了回来，导致生成用了旧缓存。解法：确认 4000 端口没有进程监听 → `rm -f db.json` → 重新 `hexo generate` → 再核验 `index.html` 的修改时间确实刷新了。

七、日常高频问题速查

症状 原因与解法
新文章不在首页/归档列表 旧 db.json 缓存 → 停服务、rm -f db.json、重新 generate（见第六节）
某段代码/HTML 显示成转义源码 那行 HTML 开头缩进了 → 顶格重写
提示框没颜色/没边框 note 写错（比如少 --warn 后缀），检查 class 拼写
图片裂了 路径没带 /Blog/ 前缀，或文件不在 source/images/
改了标题但网址没变 URL 由文件名决定，与 title 无关
本地 /Blog/ 无前缀 404 root 子路径配置——用带前缀地址访问
改文章后线上没变化 重新走一遍 generate + 推送；Pages CDN 等 1~2 分钟再强刷
