电脑不定时自动重启/关机？三步定位真凶，别急着换电源

✍️ 博主 📅 令和8年9月7日 ⏱ 阅读约 13 分钟
#电脑维修 #Windows #硬件 #系统

这是「电脑维修」系列的第二篇。上一篇立了方法论：所有故障按 供电 → 硬件 → 系统 → 软件 四层、由简到繁地排查。这篇拿一个最磨人的症状实战走一遍——电脑不定时自动重启 / 关机。

场景你一定熟：游戏打到关键时刻，屏幕一黑，主机”啪”地重启；或是它放在那里不动，半夜自己关了又开。重启完一切正常，像什么都没发生过——但你知道它还会再来。

自动重启最劝退的地方在于没有现场：蓝屏好歹留一句话，重启连个遗言都不给。但别急着拆机换电源——Windows 其实每次都把死因悄悄写进了日志。修这个问题的第一步，是先弄清楚三个字：怎么死的。

一、先分清四种”死法”，方向就对了一半

自动重启不是一种病，而是四种不同故障的共同表象。下次发作时别光顾着骂，先观察它怎么死的：

你看到的现象 像什么 优先怀疑方向 会留在日志里的痕迹
屏幕先闪一下蓝屏，瞬间自动重启 蓝屏 驱动 / 系统 / 内存 / 硬盘 BugCheck（事件 1001）
瞬间全黑、声音戛然而止，像被拔了插头，然后自己开机 断电 过热保护、电源、供电接触 只有 Kernel-Power 41
画面先卡死几秒，再黑屏重启 死机 内存 / 主板 / 驱动 BugCheck 或 41
高负载必死：一进游戏、一渲染就重启，轻载没事 过热 / 供电不足 散热、电源功率 只有 41，且集中在负载时段

同样一条”自动重启”，蓝屏型要去查驱动，断电型要去查电源——方向错了，换十个配件也修不好。

但先别急着分类。动日志之前，花一分钟排除下面这四种”假故障”，很多”自动重启”其实根本不是故障。

※ 四种常被误认成"自动重启"的情况① Windows 更新计划重启：重启时间有规律（比如固定每周的某天、深夜两点），多半是更新计划，看事件日志里有没有来源为 User32、事件 ID 1074 的"正常关机请求"即可确认。② 睡眠被唤醒：按一下鼠标/键盘就亮屏，看着像自己开机，其实只是从睡眠醒来。③ 断电后来电自启：台式机 BIOS 里 Restore on AC Power Loss 设成了 Always On——邻居装修、插排上大功率电器启停导致市电闪断，来电后它就自己开了。④ 重启键卡住 / 前置面板排线搭线：按键按下去弹不回来，会不停触发重启。

自检的产出是一句话描述，例如”只有玩大型游戏时重启，平时办公从不“或”完全随机，半夜待机也重启“——这句话决定了你走下面哪条路线，也方便你之后对照日志。顺手记到维修日志里（格式见文末）。

三、关键准备：让下一次故障”留证据”

Windows 默认设置是蓝屏后约 1 秒自动重启——这就是为什么很多人觉得”根本没蓝屏”。先把这个设置关掉，下次故障才能留下蓝屏画面：

texttext
1
2
3
4
1. Win+R → 输入 sysdm.cpl 回车（或：设置 → 系统 → 关于 → 高级系统设置）
2. 切到「高级」选项卡 → 「启动和故障恢复」→ 点「设置」
3. 在「系统失败」一栏，取消勾选「自动重新启动」
4. 确定，完成

预期看到：蓝屏不再一闪而过，而是停在画面上等你拍照。如果之后又出问题，蓝屏上会有错误代码（如 MEMORY_MANAGEMENT）和报错文件（如 nvlddmkm.sys）——拍照记下来，这正是上一篇蓝屏排查要的三样东西。

四、看日志：给故障做一次”尸检”

Windows 把所有崩溃记录都放在事件查看器里：

texttext
1
2
3
4
1. Win+R → 输入 eventvwr.msc 回车 → 打开「事件查看器」
2. 左侧展开：Windows 日志 → 系统
3. 点「日期和时间」列排序，从最新的 Kernel-Power 41 开始往下看
4. 找到它「前面」相邻的错误记录——真正的死因就藏在这里
⚠️ Kernel-Power 41 是"结果"，不是"原因"事件 ID 41（来源 Kernel-Power）的意思是"系统在未先正常关机的情况下重新启动了"——它只是告诉你**死得不够体面**。断电、蓝屏、过热保护、电源故障都会留下它，所以它几乎每次意外重启都会出现。真正决定排查方向的是 41 事件**之前那一条**记录。看到 41 就断定电源坏了去换电源，是这篇故障里最常见的白花钱操作。

每次意外重启后开机，都会新记一条 Kernel-Power 41，所以41 出现的次数 ≈ 意外重启的次数，可以用来数数问题有多频繁。但方向要看它前面的邻居：

41 之前紧邻的日志 说明什么 走哪条路线
来源 BugCheck（事件 1001，蓝屏记录） 蓝屏后自动重启 路线 A：蓝屏型
来源 WHEA-Logger（事件 18 / 19，硬件错误） CPU / PCIe 等硬件报错 查散热、超频、主板供电
什么异常都没有，只有孤零零的 41 像被直接掐了电 路线 B：高温型 → 路线 C：断电型
只有来源 User32 的 1074（正常关机请求） 软件 / 系统主动重启 不是硬件故障，查更新计划与软件
💡 更直观的替代品不想在事件列表里翻，可以 Win+R → 输入 perfmon /rel 打开可靠性监视器，它把每次崩溃画在时间轴上（红色叉号），点开就能看到当时的详细信息，判断"重启前发生了什么"比事件查看器友好得多。定位到大致方向后，再回到事件查看器看细节。

路线 A：蓝屏型——查最近改了什么

日志出现 BugCheck，说明系统是”体面”地蓝屏后重启的，问题基本锁定在驱动、系统或内存。按上一篇的方法来：

1. 回忆蓝屏前你改了什么：装的新驱动 / 新软件 / 新硬件？→ 先卸掉它
2. 记下蓝屏错误代码 → 对照上一篇第六节的蓝屏速查表
3. 进安全模式 → 管理员命令行跑 sfc /scannow，修不了再跑
   DISM /Online /Cleanup-Image /RestoreHealth
4. 怀疑显卡驱动 → 用 DDU 彻底卸载后重装最新稳定版

预期看到：卸载嫌疑驱动 / 修复系统文件后，蓝屏不再出现。如果你愿意深挖，后面的系列文章会专门讲怎么读蓝屏内存转储文件（dump），精确到是哪个驱动干的。

路线 B：高温型——高负载必死，先查散热

规律是”一玩游戏 / 一渲染就重启，浏览网页没事”，这类十有八九是温度撞墙：CPU 或显卡过热触发保护，瞬间断电重启。因为它也是瞬间断电，所以日志里同样只有 Kernel-Power 41——这就是为什么断电型排查要先排除温度。

验证与定位：

1. 装 HWiNFO（免费），先看空闲温度：台式机 CPU 待机 40~60℃ 算正常
2. 跑 AIDA64「系统稳定性测试」单拷 FPU，或干脆打一把会重启的游戏
3. 看满载最高温：CPU 到 90℃+ 已经很危险，100℃ 左右就是撞墙关机；
   GPU 90℃+ 也偏高
4. 手摸机箱出风口 / 听风扇——是不是积灰堵死、风扇不转、转速异常？

预期看到：温度读数证实撞墙（比如满载直冲 100℃），而不是电源问题。

解决（务必断电后操作）：

texttext
1
2
3
4
1. 清灰：散热器鳍片、风扇、机箱进出风口，用软毛刷 + 皮老虎/吹风机冷风档
2. 换硅脂：拆下散热器，擦掉旧硅脂，重新涂薄薄一层（绿豆大小即可）
3. 检查风扇：不转 / 异响 / 转速上不去 → 换风扇
4. 笔记本：出风口堵了是通病，但拆机清灰可能撕保修贴——在保先走售后

预期看到：满载温度下降 15~25℃，再烤机 30 分钟不重启，即修复。

1. 供电环境：换一个墙插直插（不经过插排），避开和空调等大功率共用
   → 若不再重启，是插排老化/过载，换个好插排
2. 电源功率是否够：查你显卡的官方「推荐电源瓦数」（搜索显卡型号即可），
   电源额定功率低于推荐值 → 头号嫌疑。升级过显卡/CPU 后开始重启的尤其查这条
3. 电源老化：用了 3~5 年、功率又吃紧的电源是高发区
   → 有条件借一个同规格电源交叉测试（见下方警告）
4. 供电线接触：断电后重新插拔主板 24pin、CPU 8pin、显卡供电线，
   确认"咔嗒"到位；内存也顺手重插一遍（上一篇 4.1 节）
   → 接触不良在满载大电流时会压降，表现同样是瞬间断电
⚠️ 借电源测试的两条红线① 全程断电操作，严禁带电插拔供电线。② 模组电源的线材不通用——不同品牌/型号的模组线线序不同，混插轻则不开机，重则烧毁硬盘和主板。借电源测试要连电源自带的原装线一起借。

预期看到：问题在哪个环节，替换后该环节就不再复发；若查完电源和接触仍重启，退回路线 D。

路线 D：随机型——待机也重启，查内存与主板

完全不挑负载、深夜闲置也会重启，说明不是温度和功率问题，重点怀疑内存、主板或系统底层：

1. 内存重插 + 金手指清理（上一篇 4.1 节），并做单条交叉测试
2. 快速测内存：Win+R → mdsched.exe → 重启后自动检测；
   严格测试用 MemTest86（U 盘启动，跑完 4 遍无错才算稳）
3. 清 CMOS / 恢复 BIOS 默认（上一篇 4.2 节），关掉 XMP/EXPO 或超频设置试试
   → 不稳定超频是随机重启的常见隐形元凶
4. 最小系统法（上一篇 4.3 节）：只留主板+CPU+单内存+核显，
   能开机再逐个装回——哪个装回去就重启，就是哪个

预期看到：内存测试报错 → 换内存；清 CMOS 后不再重启 → 超频设置问题；最小系统法锁定了出问题的部件。

💡 两个"软件层"冷门嫌疑如果重启总发生在电脑闲置一会儿之后（而不是满载时），试试关掉两个省电开关：① 控制面板 → 电源选项 → 更改计划设置 → 更改高级电源设置 → PCI Express → 链接状态电源管理 → 设为"关闭"（部分主板的 ASPM 与设备不兼容会导致随机重启）；② 电源选项里关闭"快速启动"（快速启动的休眠文件偶尔损坏也会引发奇怪问题）。

别一上来就拆机。按这个顺序走，每完成一步就正常用几天再决定下一步：

第 0 步  关掉蓝屏自动重启（2 分钟）——为下次故障留证据
第 1 步  排除"假重启"：更新计划 / 睡眠唤醒 / 来电自启（观察 1~2 天）
第 2 步  读事件日志，判定死法（10 分钟）
第 3 步  按路线 A/B/C/D 排查：软件 → 温度 → 电源 → 内存/接触
第 4 步  还不行 → 最小系统法锁定范围 → 考虑送修

信号 做法

七、验证与预防

怎么确认真的修好了：

texttext
1
2
3
1. 压力复现：AIDA64 双拷 30 分钟不重启（修复前在这个负载下必死）
2. 再打 1 小时游戏 / 跑一次原来必崩的场景
3. 观察一周：事件查看器里不再新增 Kernel-Power 41

三条都过，基本可以放心。如果只是”最近没犯”，别急着宣布胜利——随机性故障需要时间检验，一周无复发是最低标准。

预防清单（按性价比排序）：

  • 每半年给台式机清一次灰，电源进灰同样影响散热和寿命
  • 升级硬件前先算供电：整机满载功耗 × 1.3 ≤ 电源额定功率；换显卡直接对照官方推荐瓦数
  • 别长期开着不稳定超频跑——要超频先过稳定性测试
  • 更新 Windows 与驱动：不少”随机重启”其实是厂商已修复的 bug
  • 重要数据始终有备份——自动重启有时是硬盘或内存开始老化的前兆（铁律二：先备份，再折腾）

八、避坑与经验

⚠️ 三个最贵的坑① 看到 Kernel-Power 41 就换电源——它只是"结果"，先看 41 前面的日志，先排除温度。② 断电前手痒拆机 / 带电插拔供电线——静电和带电操作是"修好前先修坏"的头号原因（铁律一）。③ 故障复发时反复强制断电测试——每次都可能是对硬盘的一次伤害，改用"关掉自动重启让它蓝屏停住"的方式取证。
💡 三条实战心得① 每次崩溃记一行时间线："几点、在干嘛、前 10 分钟装了什么"，回头和日志对时间，定位速度翻倍。② 显卡驱动偶尔崩一下只是"黑屏 1 秒自己恢复"（Windows 的 TDR 机制），这不算重启，别混为一谈。③ 换配件排查时一次只换一个（铁律三），并且优先用借来的备件替换测试，别一上来就下单买新电源。

【结论】电源功率不足，换 750W 电源解决——升级显卡必须同步评估电源

这就是为什么修这类问题一定要先看日志、先排除温度：案例 A 清灰几十块钱解决，案例 B 换电源几百块解决——如果顺序反了，两个案例都要多花一倍的冤枉钱。
