零成本拥有自己的博客：Hexo + GitHub Pages 完整部署指南

✍️ 博主 📅 令和8年9月3日 ⏱ 阅读约 10 分钟
#Hexo #GitHub #教程

很多人对”有自己的博客”的第一反应是买服务器、装 WordPress、再去备案——其实对个人技术博客来说，绝大多数需求用一个静态博客 + 免费托管就够了：写 Markdown，一条命令发布，全球 CDN 分发，连服务器维护都省了。

这篇教程基于我的真实实践（本站就是这套流程上线的），按”踩过坑之后的最短路径”来写。你不需要服务器，只需要：一个 GitHub 账号 + 本地能跑 Node.js。

为什么是 Hexo + GitHub Pages

GitHub Pages 自购云服务器
成本 免费（公开仓库） 轻量服务器 ￥50+/年起步
HTTPS 自带 要自己申请证书
访问速度 全球 CDN 看你买的区域
维护 零维护 更新系统、防攻击、续费
适合 内容型个人博客 动态应用、复杂后端

静态博客把”动态渲染”前置到构建期：你本地跑一次 hexo generate，所有页面变成纯 HTML/JS/CSS，托管方只需要把文件发给访客。速度快、没数据库、也没得可被攻击的后端。

开始前准备

  • 一个 GitHub 账号（博客仓库要 public，免费方案下私有仓库不能开 Pages）
  • 本机装好 Git，并配置好 GitHub 的 SSH 密钥（免密推送的关键）
bashbash

2
3
# 验证 SSH 是否通（能打印出你的用户名即 OK）
ssh -T git@github.com
# 期望输出：Hi <你的用户名>! You've successfully authenticated...
  • 本机装好 Node.js（LTS 即可）。装 Hexo 脚手架：
bashbash
1
npm install -g hexo-cli

第一步：本地把博客跑起来

bashbash
1
2
3
4
5
6
7
# 建站
hexo init my-blog
cd my-blog
npm install

# 本地预览：默认 http://localhost:4000
hexo server

此时你已经有一个能看的本地博客了（默认 landscape 主题）。把 source/_posts/hello-world.md 替换成你自己的文章，写完一篇就可以随时发布——先不急着改外观，部署链路通了之后再慢慢挑主题。

第二步：把站点配置指向”未来的线上地址”（最容易踩的坑）

这是整个流程里最反直觉的一步：本地都还没上线，为什么就要先写线上地址？

因为 Hexo 生成的页面里，所有资源链接（CSS/JS/图片）都要带上最终域名前缀。你的 Pages 地址长这样：

plaintextplaintext
1
https://<用户名>.github.io/<仓库名>/

比如我的仓库叫 Blog，地址就是 https://molunanli.github.io/Blog/——注意仓库名不是 <用户名>.github.io 时，站点会挂在子路径 /Blog/ 下。这必须在生成前就告诉 Hexo，否则所有资源都会 404。

打开站点根目录的 _config.yml，改两个字段：

yamlyaml
1
2
3
4
# 正式域名（上线后就用它）
url: https://molunanli.github.io/Blog/
# 子路径前缀：仓库名是什么就写什么；若仓库名是 <用户名>.github.io 则留空 ""
root: /Blog/

两个提醒：

  • url 决定分享链接、站点地图、Giscus 评论匹配的”标准地址”，部署前就要定好。用 http://localhost:4000 预览时评论、分享等功能会指向本地，容易造成线上历史数据错乱。
  • 项目根目录的 _config.yml 才是站点配置；themes/<主题>/_config.yml 是主题配置，别改混。

第三步：在 GitHub 建仓库

  1. 到 github.com 点 New repository
  2. 仓库名随意（如 Blog），必须 Public，先不要勾选初始化 README
  3. 创建完成后，把仓库地址记下来（SSH 形式）：
plaintextplaintext
1
git@github.com:<用户名>/Blog.git

第四步：部署到 gh-pages 分支（两种方式任选）

Pages 约定俗成用 gh-pages 分支来存放”生成后的站点文件”（也可以选 main 分支的 /docs 目录，但 gh-pages 最省心，源码和产物互不干扰）。

方式 A：hexo-deployer-git（新手推荐）

bashbash
1
2
# 在博客目录安装部署插件
npm install hexo-deployer-git --save

然后给站点 _config.yml 的末尾加上：

yamlyaml
1
2
3
4
deploy:
  type: git
  repo: git@github.com:<用户名>/Blog.git   # SSH 形式免密
  branch: gh-pages

之后每次发布只要三条命令：

bashbash
1
hexo clean && hexo generate && hexo deploy

deploy 插件会自动把 public/ 里的产物推到远端 gh-pages 分支。

方式 B：手动 git 推送（想完全掌控时）

hexo deploy 本质就是”把 public 推到一个分支”。不想装插件、或者想看清每一步时，可以手动做：

bashbash
1
2
3
4
5
6
7
8
9

hexo generate

# 把产物目录变成一个独立的 git 仓库，推到 gh-pages
D=".dpl_$(date +%s)"
mkdir -p "$D" && cd "$D"
git init -q && git checkout -q --orphan gh-pages
cp -rf ../public/. .
git add -A
git -c user.name="<用户名>" -c user.email="<邮箱>" commit -q -m "deploy $(date +%Y-%m-%d)"
git push -q -f git@github.com:<用户名>/Blog.git gh-pages

--orphan 新建一个”没有历史的分支”，-f 强制覆盖——产物分支每次都整体重推，简单粗暴且不会有冲突。

第五步：启用 GitHub Pages（只需要点两下）

推送完 gh-pages 分支后，打开仓库的 Settings → Pages：

  1. Source 选 Deploy from a branch
  2. Branch 选 **gh-pages**，目录保持 / (root)
  3. Save

等 1~2 分钟，你的博客就上线了：

plaintextplaintext
1
https://<用户名>.github.io/<仓库名>/

验证三步曲：

bashbash
1
2

# 1. 首页能访问（返回 200）
curl -I https://<用户名>.github.io/<仓库名>/

# 2. 首页 CSS 是否真的加载出来——检查 HTML 里的资源链接带了 /Blog/ 前缀
curl -s https://<用户名>.github.io/<仓库名>/ | grep -o 'href="[^"]*css[^"]*"'

# 3. 多刷新几次（Ctrl+F5）——Pages 有 CDN，刚发布可能还是旧缓存

日常更新：写文章、发文章

本地继续写 source/_posts/ 下的 Markdown，然后重复那条发布命令：

bashbash
1
hexo clean && hexo generate && hexo deploy

源文件（source/、themes/、_config.yml）不需要推到 GitHub——gh-pages 分支上只有生成产物。如果想让源码也有个异地备份，单独建个私有仓库放源码即可，两边互不干扰。

进阶：让它更省心或更像”个人站点”

1. GitHub Actions 自动部署（想”推送即发布”）

适合多设备写作的场景：本地只维护源码，推到 main 分支后由 GitHub 的服务器自动完成构建和发布。在仓库根目录放一个 workflow 文件：

yamlyaml
1
2
3
4
5

7
8
9

21
# .github/workflows/deploy.yml（放在源码仓库里）
name: Deploy Hexo
on:
  push:
    branches: [main]
permissions:
  contents: write
jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 20
      - run: npm ci
      - run: npx hexo generate
      - uses: peaceiris/actions-gh-pages@v4
        with:
          github_token: ${{ secrets.GITHUB_TOKEN }}
          publish_dir: ./public

用这个方案的话，_config.yml 的 deploy 段就不需要了。

2. 绑定自己的域名

在仓库 Settings → Pages → Custom domain 填你的域名，并在域名服务商加一条 CNAME 记录指向 <用户名>.github.io。想强制 HTTPS 就勾上 Enforce HTTPS。GitHub 会替你自动申请证书。

3. 给文章加评论区

纯静态站没有数据库，评论可以交给第三方托管服务。本站用的是 Giscus：评论直接存到 GitHub Discussions 里（顺便自带 reaction 点赞），零后端零数据库。相关配置方法可以看我归档页那套热力图的思路——凡是”静态站想要动态数据”，思路都是找一个免费的持久化载体外挂。

常见坑汇总

症状 原因 解法
页面能开但全是裸 HTML，没有样式 root 没配或配错，资源 404 _config.yml 里 root: /<仓库名>/
推送后 1 分钟还是旧页面 Pages CDN 缓存 等 1~2 分钟再 Ctrl+F5 强刷
hexo deploy 报错/超时 网络连 GitHub 慢，或没配 SSH 用 ssh -T git@github.com 自查；改用手动 git 推送
本地预览一切正常、线上 404 页面请求的是 http://localhost:4000/... 生成前把 url 改成正式域名
私有仓库开不了 Pages 免费账户 Pages 需要 public 仓库设为 Public
hexo clean 提示删不掉文件 Windows 上可能是文件被占用/权限 先停掉 hexo server 再 clean

最后一点心态建议：先让链路通，再谈美化。第一篇文章能从一个公开网址打开，博客就算立起来了——主题、域名、评论、统计都是之后的水到渠成。折腾的过程本身，就是你的第一篇文章素材。
